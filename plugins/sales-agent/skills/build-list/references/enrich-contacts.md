# 連絡先取得リファレンス

営業先候補の公式サイトを探索し、連絡先情報（メールアドレス・問い合わせフォームURL）を取得する手順。

## 入力

営業先候補のリスト。各候補には最低限以下が含まれる:
- `company_name`: 法人名・学校名等
- `website_url`: 公式サイトURL
- `overview`: 事業概要
- その他 build-list Phase 1 で取得済みの情報（industry 等）

## 探索手順

各候補について、以下の順で探索する。**メールアドレスの取得を最優先**し、見つからない場合のみフォームURLを探す。

### 1. メールアドレスの探索

公式サイト内の以下のページを順にWebFetchで確認する:

1. **トップページ** — フッターやヘッダーにメールアドレスが記載されていることが多い
2. **お問い合わせページ** — `/contact`, `/inquiry`, `/お問い合わせ` 等
3. **会社概要・法人情報ページ** — `/about`, `/company`, `/corporate` 等
4. **アクセス・所在地ページ** — 住所とともにメールが記載されていることがある

探索のポイント:
- `info@`, `contact@`, `sales@`, `support@` 等の代表メールアドレスを探す
- 個人名メールアドレスではなく、組織の代表アドレスを優先する
- ページ内に `mailto:` リンクがあれば抽出する
- フッターに記載されているメールアドレスはほぼ全ページ共通なので、トップページで見つかればそれで十分

### 2. 問い合わせフォームURLの探索（メールが見つからない場合のみ）

メールアドレスが見つからなかった場合に限り、問い合わせフォームを探す。

**適切なフォーム（登録してよい）:**
- 「お問い合わせ」「ご相談」等の汎用的な問い合わせフォーム
- 「法人のお客様」「業務提携」等のB2B向けフォーム

**不適切なフォーム（登録しない）:**
- 「資料請求」「入学相談」「採用応募」「体験申込」等の用途限定フォーム
- 電話番号・生年月日等の不要な個人情報が必須項目のフォーム
- 404やリンク切れのフォーム

フォームURLを登録する場合は、実際にページにアクセスしてフォームの種別・必須項目を確認した上で判断する。

### 3. SNSアカウントの確認（余裕があれば）

公式サイト上にSNSリンク（Twitter/X, LinkedIn等）があれば取得する。ただしメール・フォームの探索を優先し、SNSは見つかれば拾う程度でよい。

## 出力

各候補について、取得した情報をJSON形式で返す:

```json
[
  {
    "company_name": "A社",
    "website_url": "https://a.com",
    "overview": "事業概要",
    "industry": "業種",
    "email": "info@a.com",
    "contact_form_url": null,
    "sns_accounts": {"x": "@a_official"},
    "match_reason": "...",
    "priority": 3
  }
]
```

- `email` が見つかった場合は `contact_form_url` は不要（null でよい）
- 両方見つからなかった場合は、両方 null のまま返す（登録はするが、outbound時にスキップされる）
- Phase 1 で渡された `match_reason`, `priority` 等の情報はそのまま維持して返す
